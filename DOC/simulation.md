# 시뮬레이션 — 사용자 한 명의 하루, 기술까지

> 2026-11-23. 창업자의 말(브리프 ★-6)을 제품으로 끝까지 돌려본 것. 사용자는 창업자 본인. iPhone(iOS 26), 애플워치 있음[가정], 애플 AI 안 씀(결정), 알람은 시계 앱(결정).
> 갈림길은 묻지 않고 Claude가 골랐다. 고른 자리는 **[가정]**. 창업자는 틀린 줄만 말하면 되고, 그러면 전체를 다시 돌린다.

## 0. 설정값 (온보딩에서 받은 것)

| 항목 | 값 | 어디서 |
|---|---|---|
| 수면 시간 | 7시간 | 사용자 입력 |
| 기상 시각 | 6:30 | 사용자 입력 |

| 칼로리 | 목표 섭취 2,200 kcal | [가정] 사용자 입력 또는 키·몸무게에서 계산 |

## 1. 하루 — 화요일

표기: **화면** = 사용자가 보는 것 · **뒤에서** = 그 순간 실제로 도는 것 · **데이터** = 어디서 와서 어디로 가나.

### 06:30 — 알람

- **화면**: 시계 앱 알람. 우리 것 아님.
- 사용자가 끈다.
- **뒤에서**: 아무것도. 우리 앱은 자고 있다.

### 06:30 — 잠금화면 카드

- **화면**: 알람을 끄면 잠금화면에 우리 카드(Live Activity). "오늘의 첫 한 가지 · 물 한 잔 마시고 창문 열기 · [시작]". 이 카드는 **어젯밤 22:50부터 떠 있던 것**이 아침 모드로 바뀐 것.
- **뒤에서**: 카드의 아침 전환은 **서버가 06:30에 보낸 Live Activity 푸시**(ActivityKit push). 앱이 깨어날 필요 없음. [가정] Live Activity는 8시간 상한이 있어 22:50에 시작한 것이 06:50까지 산다. 06:30 푸시는 그 안에 들어온다. 더 길게 가야 하면 서버가 06:00에 push-to-start로 새 카드를 띄운다.
- **데이터**: "물 한 잔 마시고 창문 열기"는 어젯밤 21:30 서버 배치가 만들고 사용자가 22:20에 확정한 문장. 서버에 있고, 푸시로 카드에 실린다.

### 06:31 — "시작"

- **화면**: [시작]을 누르면 카드가 "물 한 잔 마시고 창문 열기 · 시작됨 06:31"로 바뀐다. 앱은 열리지 않는다.
- **뒤에서**: 카드 버튼 = App Intent. 앱 프로세스가 백그라운드에서 몇 초 깨어나 (1) 로컬 기록 "첫 한 가지 시작 06:31", (2) 서버에 한 줄 전송, (3) Live Activity 상태 갱신.
- **데이터**: 기상 시각 = **몸으로 확인**. 06:31의 탭이 1차 근거. 2차는 HealthKit 수면 종료(워치가 기록, 수십 분 뒤 앱에 전달)와 첫 걸음. 셋이 어긋나면 탭을 믿는다 [가정].
- 안 눌렀으면: 카드는 06:50까지 남아 있다가 사라진다. 07:30에 서버가 다시 한 번 카드를 띄운다 [가정: 한 번만, 잔소리 금지]. 그래도 안 누르면 "오늘 첫 한 가지 없음"으로 기록되고 밤에 AI가 내일 것을 더 작게 만든다.

### 06:45 — 홈 위젯, 하루 모드

- **화면**: 홈 첫 페이지의 큰 위젯 하나. "오늘 · ✓ 물 한 잔 06:31 · 오늘의 세 가지: ① 투자 메일 답장 ② 사이클 1 화면 그리기 ③ 웨이트 19:00 · 다음 일정 10:00 미팅".
- **뒤에서**: 위젯은 **타임라인**이다. 어젯밤 22:20 확정 직후 앱이 오늘 하루치 타임라인(06:30 아침 모드 / 06:45 하루 모드 / 19:00 운동 모드 / 22:30 밤 모드)을 미리 만들어 WidgetKit에 넘겨뒀다. 06:31의 탭이 타임라인을 다시 만든다(App Intent 안에서 `reloadTimelines`).
- **데이터**: 세 가지는 어젯밤 서버가 캘린더(EventKit)·어제 못 끝낸 것·운동 계획에서 초안을 만들고 사용자가 확정한 것. 캘린더 일정은 위젯이 그릴 때 EventKit에서 직접 읽는다(권한 있으면 위젯 확장에서 읽기 가능 [가정: 확인 필요]).

### 08:10 — 아침 식사

- **화면**: 위젯의 "먹은 것 · 0 / 2,200" 줄을 누르면 **앱이 열린다** (하루 중 앱이 열리는 몇 안 되는 순간). 카메라가 바로 뜬다. 사진 한 장. 2초 뒤 "계란 2개, 토스트 1장, 커피 · 약 420 kcal · 단백질 18g" + [맞음] [고치기].
- **뒤에서**: 사진 → 서버(비전 모델) → kcal·단백질 추정 → 앱이 HealthKit에 `dietaryEnergyConsumed` 기록 → 위젯 타임라인 갱신.
- **데이터**: AI 비용이 사용자 수에 비례하는 유일한 낮 작업. [가정] 사진 1장당 추정 비용은 작고(비전 모델 1회), 하루 3~4회. 사진 대신 한 줄 입력("김치찌개 한 그릇")도 같은 경로.
- 안 찍으면: 아무 일도 없다. 밤 확정 화면에 "오늘 먹은 것 기록 1/3" 정도로만 보인다.

### 09:00~18:00 — 일과

- **화면**: 위젯이 전부. 세 가지 중 하나를 누르면 "시작" → 잠금화면에 Live Activity "② 사이클 1 화면 그리기 · 42분". 끝내면 체크.
- **뒤에서**: 세션 시작 = App Intent → Live Activity 시작(앱 프로세스에서 가능) + 로컬 기록. [가정] 일과 중에는 **차단 없음**. 사용자가 세션 중 "조용히" 토글을 켜면 그 세션 동안만 실드(ManagedSettingsStore에 토큰 적용). 토글은 Live Activity 버튼.
- **데이터**: 세션 시간은 우리 기록. 스크린타임 숫자는 애플이 안 주므로 **쓰지 않는다**.
- 10:00 미팅처럼 캘린더에 있는 일정은 위젯이 "다음 일정"으로 보여줄 뿐 건드리지 않는다.

### 12:30 — 점심

- 08:10과 같다. 위젯 "420 / 2,200" → 사진 → "약 780 kcal" → 위젯 "1,200 / 2,200".

### 19:00 — 운동

- **화면**: 18:55 잠금화면 카드 "5분 뒤 웨이트 · [시작]". 누르면 Live Activity "웨이트 · 00:00 · 0 kcal". 워치에도 같은 카드(Smart Stack). 운동 중 인스타를 열면 **실드**: "웨이트 50분 중 · 끝나고 봐요 · [끝났어요]".
- **뒤에서**: 18:55 카드 = 서버 푸시(push-to-start). "시작" = App Intent → (1) Live Activity 시작, (2) 조용히 할 앱에 실드 적용(ManagedSettingsStore), (3) [가정] HealthKit 운동 세션은 **워치가** 기록한다 — 워치 운동 앱을 우리가 띄울 수는 없고, 사용자가 워치에서 운동을 시작하거나(안내), 폰 Live Activity의 kcal은 HealthKit `activeEnergyBurned`를 1분마다 읽어 보여준다(앱이 전면이 아니면 갱신이 늦을 수 있음 — Live Activity 갱신은 앱 프로세스 또는 푸시만 가능, 워치 데이터는 백그라운드 전달이 시간당 1회 수준). **현실적 화면**: 운동 중에는 "경과 시간"만 실시간이고 kcal은 끝난 뒤 정확해진다.
- "끝났어요" → 실드 해제, Live Activity 종료, HealthKit에서 이 시간대 활동 에너지 읽어 "웨이트 52분 · 410 kcal" 기록.
- **데이터**: 소모 kcal = HealthKit(워치). 워치 없으면 걸음 기반 추정이라 웨이트는 거의 0 → [가정] 워치 없는 사용자에겐 "운동 시간"만 보여주고 kcal은 안 보여준다.

### 20:00 — 저녁 + 하루 수지

- 식사 사진 → "약 650 kcal" → 위젯 "먹은 것 1,850 / 2,200 · 쓴 것 2,310 (기초 1,900 + 운동 410)". 하루 수지 한 줄.
- [가정] 기초대사량은 HealthKit `basalEnergyBurned`(워치) 또는 키·몸무게 공식.

### 21:30 — 서버 배치 (사용자는 모름)

- **뒤에서**: 서버가 이 사용자의 오늘을 모아 **내일 초안**을 만든다. 입력: 오늘 기록(첫 한 가지 시작 여부, 세 가지 완료 수, 세션 시간, 식사, 운동), 어젯밤 수면(HealthKit, 앱이 마지막으로 동기화한 것), 내일 캘린더(앱이 동기화), 실드 뚫은 횟수, 요일. 출력: 내일 첫 한 가지 한 문장, 내일 세 가지 초안, 실드 문구 3종(밤·운동·낮), 내일 kcal 예산(운동 요일이면 +), 한 줄 코멘트 없음(말하지 않는다).
- **데이터 동기화의 현실**: 앱이 백그라운드에서 서버로 데이터를 보내는 시점은 (1) App Intent로 깨어날 때마다(탭할 때), (2) HealthKit 백그라운드 전달로 깨어날 때(시간당 1회 수준), (3) BGAppRefreshTask(시스템이 정함, 30초). 21:30 배치가 쓰는 데이터는 "마지막 동기화 시점"까지. [가정] 충분하다 — 하루의 입력은 거의 전부 탭에서 오니까.
- **AI 비용**: 사용자당 하루 1회 텍스트 생성(작은 프롬프트) + 식사 사진 3~4회. 예측 가능.

### 22:20 — 밤 10초 (하루의 유일한 "앱 화면")

- **화면**: 알림 "내일 준비됐어요". 누르면 앱이 열리고 **한 화면**: "오늘 · 첫 한 가지 ✓ · 세 가지 2/3 · 웨이트 52분 · 1,850 / 2,310 kcal · 뚫음 1" 위에, 아래에 "내일 · 기상 6:30 · 첫 한 가지: 스트레칭 5분 · 세 가지: ① ② ③ · 웨이트 쉬는 날". 각 줄은 탭하면 고칠 수 있다. 맨 아래 [좋아요]. 10초.
- **뒤에서**: 22:20 알림 = 서버 푸시(일반 알림). [좋아요] → 서버에 확정 전송 → 앱이 내일 위젯 타임라인 생성 → 실드 확장이 읽을 문구를 App Group에 저장 → 끝.
- 안 열면: 초안이 그대로 확정된다 [가정]. 22:50 카드도 초안으로 뜬다.

### 22:30 — 조용해진다

- **화면**: 인스타를 열면 **실드**(애플 템플릿). 제목 "내일 6:30, 스트레칭 5분을 위해." 부제 "오늘은 끝 · 뚫음 1". 버튼 [오늘 끝] [5분만].
- **뒤에서**: 실드는 **DeviceActivitySchedule**(22:30~06:30, 매일)이 켜질 때 DeviceActivityMonitor 확장이 ManagedSettingsStore에 토큰을 적용. 확장은 6MB 메모리, 네트워크 없음 — 그래서 문구는 22:20에 미리 App Group에 저장해 둔 것을 ShieldConfiguration 확장이 읽는다. 스케줄이 **제때 안 켜지는 버그**(iOS 26.x)가 있으므로 [가정] 22:20 확정 때 앱이 전면에 있으면 그 자리에서 ManagedSettingsStore에 22:30 적용을 **직접** 예약하지 못하므로(앱은 22:30에 깨어 있지 않음) 스케줄에 의존할 수밖에 없다. 대신 22:50 카드 푸시가 올 때 실드 상태를 확인할 수는 없다(읽기 API 없음). → **실드가 안 켜진 밤은 그냥 안 켜진다.** 밤 확정 화면에 "어젯밤 조용해지지 않았음"을 다음 날 보여주는 것으로 솔직하게 간다.
- [5분만] → ShieldAction 확장이 5분 유예(ManagedSettingsStore에서 그 토큰만 잠시 제거 + 5분 뒤 재적용은 DeviceActivity 이벤트로 — 최소 단위 15분이라 **실제로는 15분**[가정: "5분만"이 아니라 "15분만"으로 바꾼다]) + App Group에 "뚫음 +1".

### 22:50 — 잠금화면 카드, 밤 모드

- **화면**: "40분 뒤 취침 · 내일 첫 한 가지: 스트레칭 5분 · [확인]". 확인은 안 눌러도 됨.
- **뒤에서**: 서버가 22:50에 push-to-start로 Live Activity 시작. 이 카드가 아침 06:30까지 살아서(8시간 상한 안) 아침 모드로 바뀐다.

### 23:30 — 취침

- **화면**: 아무것도. 폰은 그냥 조용하다.
- **데이터**: 실제 취침은 워치가 잔다(HealthKit 수면). 내일 21:30 배치에 들어간다.

## 2. 기술 뼈대 (무엇이 어디서 도나)

| 조각 | 어디서 | 하는 일 | 깨어 있는 시간 |
|---|---|---|---|
| **본 앱** (iPhone) | 전면 | 온보딩, 식사 사진, 밤 10초 화면 | 하루 합쳐 5분 이하 |
| **App Intents** | 앱 프로세스, 백그라운드 몇 초 | 위젯·카드 버튼(시작·끝·확인·조용히) → 로컬 기록 + 서버 전송 + 타임라인/Live Activity 갱신 | 탭할 때마다 |
| **홈 위젯** (WidgetKit) | 위젯 확장 | 하루 타임라인(아침·하루·운동·밤 모드) 그리기 | 타임라인대로 |
| **Live Activity** (ActivityKit) | 위젯 확장 + 서버 푸시 | 잠금화면 카드: 밤·아침·운동·세션 | 8시간 상한 |
| **DeviceActivityMonitor 확장** | 시스템이 띄움, 6MB | 22:30~06:30 실드 적용·해제 | 스케줄 시각 |
| **ShieldConfiguration 확장** | 시스템이 띄움 | 실드 화면 문구(App Group에서 읽음) | 실드 뜰 때 |
| **ShieldAction 확장** | 시스템이 띄움 | [오늘 끝]/[15분만] 처리, 뚫음 카운트 | 버튼 누를 때 |
| **워치 앱** [가정: 사이클 2] | 워치 | 카드 표시, 시작/끝 버튼, 운동 기록은 워치 기본 앱 | — |
| **서버** | 우리 | 사용자별 하루 기록 저장, 21:30 배치(AI), 푸시 4종(06:30 카드 전환 · 18:55 운동 카드 · 22:20 알림 · 22:50 밤 카드), 식사 사진 추정 | 상시 |
| **AI** (외부 모델, 애플 아님) | 서버 | 밤 배치 텍스트 생성, 식사 사진 추정 | 사용자당 하루 1 + 3~4회 |

**앱이 스스로 깨어나는 방법은 없다.** 전부 (a) 사용자의 탭, (b) 시스템 스케줄(DeviceActivity), (c) 서버 푸시, (d) HealthKit 백그라운드 전달, 넷 중 하나로 깨어난다. 하루 흐름의 모든 시각은 이 넷 중 하나에 걸려 있다. 서버 푸시가 가장 믿을 만하고, DeviceActivity가 가장 못 믿는다.

## 3. 안 되는 것 (설계가 피해 간 자리)

1. **스크린타임 숫자**를 앱이 못 읽는다 → "오늘 인스타 1시간 23분" 같은 화면은 없다. 대신 "뚫음 횟수"와 우리 세션 시간만.
2. **실드는 설정 토글로 풀린다** → 강제하지 않는다. 뚫은 날은 다음 날 밤 화면에 숫자로만.
3. **앱이 Focus·알림·홈 배치를 못 바꾼다** → 온보딩에서 사용자가 손으로. 카톡 알림을 줄이는 건 우리가 못 하고 안내만.
4. **DeviceActivity 최소 15분** → "5분만"은 "15분만".
5. **실드 화면은 애플 템플릿** → 문장·버튼·색까지만.
6. **앱이 알람을 못 건다** → 시계 앱. 알람 화면에 우리 문장 없음.
7. **워치는 차단 못 함, 운동 세션을 우리가 못 띄움** → 워치는 보여주고 누르는 기기. 운동 기록은 워치 기본 앱.
8. **Live Activity 8시간** → 밤 22:50~06:50 한 번, 아침 전환은 푸시로.
9. **위젯 안에서 캘린더 읽기** [가정: 가능]. 안 되면 앱이 타임라인 만들 때 넣어둔다.

## 4. 가정 목록 (창업자가 "아니"라고 할 수 있는 것)

1. 디지털 선셋 = 취침 1시간 전.
2. 운동은 요일·시각·종류 세 칸 입력. AI 제안은 쉬는 날 조정 정도.
3. 칼로리 목표는 사용자 입력(또는 키·몸무게).
4. 일과 중 차단 없음. 세션 중 "조용히" 토글만.
5. 첫 한 가지를 안 누르면 07:30에 한 번만 다시 띄움. 잔소리 없음.
6. 밤 10초를 안 열면 초안이 그대로 확정.
7. 식사는 사진 또는 한 줄. 서버 비전 모델. 하루 3~4회 비용.
8. 워치 없는 사용자는 운동 kcal을 안 보여줌.
9. "5분만"은 15분.
10. 워치 앱은 사이클 2.
11. 실드가 안 켜진 밤은 숨기지 않고 다음 날 보여준다.
12. AI는 말하지 않는다. 코멘트 줄 없음. 숫자와 문장(첫 한 가지·세 가지·실드 문구)만 만든다.
