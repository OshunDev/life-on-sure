# 모듈 공통 틀

> 상태: **초안** (2026-11-03). 표기: [결정] · [제안] · ⚠️ 창업자가 정할 것
> 창업자: "모듈을 먼저 모두 완성해야 Sure에 의미가 생기고, 거기서 Sure를 어떻게 풀지가 나온다."

---

## 1. 모듈이란 [지금까지의 결정 정리]

- 삶은 이미 모듈화되어 있다: **운동 · 식사 · 일 · 수면.**
- 모듈은 **정직하게 잰다.** 판단하지 않는다. 해석은 Sure의 몫.
- 모듈은 **규칙 기반이고 무료.** AI 없이도 동작한다.
- 목표는 모듈에 묶이지 않는다. 모듈은 목표의 **재료**이자, Sure가 내 삶을 저절로 아는 **감각.**

## 2. 모듈이 지켜야 할 원칙 [제안]

1. **Sure 없이도 쓸 만해야 한다.** 무료 사용자는 모듈만 쓴다. 모듈 하나만으로도 "이거 좋다"가 나와야 한다.
2. **재는 것은 한두 개.** 심플함이 원칙. 많이 잴 수 있어도 보여주는 핵심은 하나.
3. **사용자의 수고는 0에 가깝게.** 자동 → 사진 한 장 → 탭 한 번 순으로 우선.
4. **기준은 과학에서.** "많이"가 아니라 근거 있는 기준과 비교한다. 그리고 **내 평소와** 비교한다.
5. **정직하게.** 오차가 큰 값은 범위나 "약"으로 보여준다. 확실한 척하지 않는다.
6. **판정하지 않고 쌓인다.** 빨간색 경고, 실패 표시 없음. 한 일이 쌓이는 것을 보여준다.
7. **해로운 방향으로 밀지 않는다.** 과한 운동, 과한 절식, 수면 강박을 부추기지 않는다.

## 3. 모듈 하나를 기획하는 틀 [제안]

모든 모듈을 같은 순서로 채운다.

| # | 항목 | 질문 |
|---|---|---|
| 1 | 왜 중요한가 | 이 영역이 삶과 목표에 왜 중요한가. 근거는? |
| 2 | 이론과 기준 | 영역의 과학이 말하는 기준은? 행동을 바꾸는 이론은? |
| 3 | 무엇을 재는가 | 핵심 한 개, 보조 한두 개 |
| 4 | 어떻게 재는가 | 자동 / 사진 / 탭 / 입력, 어느 기기에서 |
| 5 | 혼자서 보여주는 것 | Sure 없이(무료) 사용자가 보는 화면 |
| 6 | Sure에게 넘기는 것 | 공통 형식 (아래 4장) |
| 7 | 목표와의 연결 | 이 모듈로 자동 확인되는 목표들 |
| 8 | 다른 모듈과 닿는 곳 | Sure가 이어서 해석할 지점 |
| 9 | 하지 말 것 | 안전, 정직, 인간성 |
| 10 | MVP 범위 | 처음에 어디까지 |
| 11 | 페르소나별 모습 | 다섯 페르소나에게 어떻게 다른가 |

## 4-0. [결정] 모듈 사이 표준화는 최소로 (2026-11-03)
- 창업자: **"모듈마다 표준화는 필요 없을 것 같다. 결국 처리하는 건 Sure이니, 데이터가 JSON으로만 정리되면 Sure가 유동적으로 판단할 수 있다."**
- **[결정 보충] 표준화를 하지 말라는 게 아니다.** 뜻은: **같은 모듈의 스타일들이(예: 모든 일 모듈 스타일이) 꼭 같은 데이터로 이루어질 필요는 없다.**
  - 표준은 유지한다: 모든 기록에 씌우는 봉투(아래), 그리고 쓸모 있는 곳의 공통 규칙(시간 표기, 단위 등).
  - 스타일마다 다른 것은 `data` 안에서 자유롭게. 타임라인형 일 스타일은 블록과 계획·실제 시간을, 오늘 목록형 일 스타일은 할 일과 완료를 담을 수 있다. 둘이 같은 칸을 가질 필요는 없다. Sure가 읽고 판단한다.
- 아래 4장의 "Sure용 공통 형식"은 강제하지 않는다.
- [제안] 단, **아주 얇은 봉투 하나만** 모든 기록에 씌운다. 이유:
  1. **홈 타임라인은 OS가 그린다. Sure가 없는 무료 사용자도 본다.** AI 없이 타임라인을 그리려면 최소한 "언제"와 "무엇"은 정해진 자리에 있어야 한다.
  2. **시간 같은 핵심 사실은 AI 해석에 맡기지 않는다.** 매번 같은 답이 나와야 하는 것.
  3. **비용.** 매번 큰 JSON 전체를 AI에 보내지 않고 봉투만 먼저 볼 수 있다.
  4. **개인정보.** 봉투에 "민감함" 표시를 두면 AI로 보낼지 말지 OS가 정할 수 있다.
  5. 나중의 UGC 마켓에서도 이 봉투가 유일한 약속이 된다.
- 봉투 (이게 전부):

  ```json
  {
    "module": "work",
    "style": "timeline",
    "start": "2026-11-03T09:00:00+09:00",
    "end":   "2026-11-03T12:10:00+09:00",
    "title": "기획서 쓰기",
    "value": "3시간 10분",
    "image": null,
    "sensitive": false,
    "data": { "...모듈과 스타일이 마음대로 정하는 자유 JSON..." }
  }
  ```
  - `data` 안은 모듈마다, 스타일마다 완전히 자유. Sure가 읽고 판단한다.
  - 깃허브 조사에서 본 ActivityWatch의 구조(시각 + 길이 + 자유 데이터)와 같은 생각.

## 4. (참고, 강제 안 함) 모듈이 Sure에게 넘기던 공통 형식 초안

모든 모듈이 같은 모양으로 말해야 Sure가 한 번에 읽고 잇는다.

| 칸 | 뜻 | 예 (운동) |
|---|---|---|
| 오늘 | 오늘의 핵심 값 | 활동 95분 |
| 이번 주 | 기준 대비 쌓인 정도 | 150분 중 310분 |
| 평소 | 최근 4주 평균 대비 | 평소보다 조금 많음 |
| 믿을 만함 | 값의 정확도 | 높음 (워치 측정) / 낮음 (추정) |
| 신호 | Sure가 주목할 사건 | 3일 연속 고강도 |
| 쌓인 것 | 판정 없는 누적 | 이번 달 운동한 날 18일 |

- "믿을 만함" 칸이 있어서 Sure는 낮은 값을 단정하지 않는다. (빈틈 9-5 해결의 실마리)

### 4-1. 순간 — 홈 타임라인에 내놓는 것 → 4-0의 봉투로 대체
홈은 오늘의 타임라인이다 (브리프 4-1). 그래서 모든 모듈은 Sure용 형식과 함께 **"순간"** 을 내놓는다.

| 칸 | 뜻 | 예 (운동) | 예 (식사) |
|---|---|---|---|
| 시각 | 언제 | 7:40 – 8:32 | 12:30 |
| 이름 | 짧은 말 | 출근 라이딩 | 점심 |
| 이미지 | 동그란 사진 한 장 | 달린 길 지도 또는 그날 풍경 | 찍은 음식 사진 |
| 핵심 값 | 하나 | 20.1km | 약 650kcal |
| 상세 | 눌렀을 때 펼쳐지는 것 | 경로, 속도, 심박 | 음식 구성, 영양 |
